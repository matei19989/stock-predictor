# Backend Tasks 21–25 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use **superpowers:subagent-driven-development** (recommended) or **superpowers:executing-plans** to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking. **Execution approach chosen: Subagent-Driven.**

**Goal:** Wire up the API entry point (`Program.cs`), create all three REST controllers (Auth, Stocks, Predictions), and generate the initial EF Core database migration — making the backend fully runnable end-to-end.

**Architecture:** `Program.cs` is the composition root: it configures Serilog, calls `AddInfrastructure(config)` to register all services/repositories/Hangfire, sets up JWT Bearer authentication with ProblemDetails-consistent challenge responses, CORS, Swagger with Bearer token support, FluentValidation auto-validation, and the middleware pipeline (CorrelationId → ExceptionHandling → SerilogRequestLogging). At startup it applies EF migrations and runs the `DataSeeder`. The three controllers are thin — they delegate entirely to service interfaces with no business logic. `AuthController` is unauthenticated (register/login); `StocksController` and `PredictionsController` require JWT `[Authorize]`. Task 25 generates the EF Core migration from the existing `AppDbContext` + entity configurations and applies it to a local PostgreSQL instance via Docker.

**Tech Stack:** .NET 9, ASP.NET Core, EF Core 9 + Npgsql, JWT Bearer, Serilog, FluentValidation, Hangfire, Swagger/OpenAPI, Docker (PostgreSQL)

**Context:** Tasks 1–20 are complete on `feature/backend-implementation`. All entities, DTOs, exceptions, validators, repositories, services, the ML client, Hangfire job, data seeder, DI registration, config files, and middleware are in place. The `DependencyInjection.AddInfrastructure` extension registers everything the application needs. The `ExceptionHandlingMiddleware` maps `AppException` subclasses to ProblemDetails. Config is in `appsettings.json` / `appsettings.Development.json` with JWT, CORS, Hangfire, DB, and ML service settings.

**Important notes:**
- **JWT ProblemDetails consistency:** ASP.NET's JWT Bearer middleware short-circuits on invalid/missing tokens and returns its own 401 (with `WWW-Authenticate` header, no ProblemDetails body). This is different from the ProblemDetails 401 our `ExceptionHandlingMiddleware` produces for `UnauthorizedException`. Task 21's `Program.cs` must configure `JwtBearerEvents.OnChallenge` to override the default and return a ProblemDetails response, so the frontend sees a consistent error format for all 401s.
- **EF Core migration:** Task 25 requires a running PostgreSQL instance (via `docker-compose up db -d`). The `dotnet-ef` CLI tool must be installed globally. Migration files are generated artifacts that go into `Infrastructure/Persistence/Migrations/`.
- **No commits from inside tasks.** Stop after Task 25 is done and the build passes.

## Task 21: Program.cs

**Files:**
- Modify: `src/backend/API/Program.cs`

Replace the default template entirely. This is the composition root that boots the full application. It must:

1. **Serilog** — bootstrap logger, then full config from `appsettings.json` with Console + File sinks + `Enrich.FromLogContext()` (so correlation IDs appear in logs)
2. **Infrastructure** — `builder.Services.AddInfrastructure(builder.Configuration)` (registered in Task 18)
3. **Controllers + FluentValidation** — `AddControllers()`, `AddFluentValidationAutoValidation()`, `AddValidatorsFromAssemblyContaining<RegisterRequestValidator>()`
4. **JWT Bearer Authentication** — read `Jwt:Key/Issuer/Audience` from config, configure `TokenValidationParameters`, and override `OnChallenge` + `OnForbidden` to return ProblemDetails for consistency with `ExceptionHandlingMiddleware`
5. **CORS** — read `Cors:AllowedOrigins` from config, create `"FrontendPolicy"`
6. **Swagger** — with JWT Bearer security definition so Swagger UI has an "Authorize" button
7. **Middleware pipeline** — order matters: `CorrelationIdMiddleware` → `ExceptionHandlingMiddleware` → `UseSerilogRequestLogging` → Swagger (dev only) → Hangfire dashboard (dev only) → CORS → Auth → Controllers
8. **Startup tasks** — apply EF migrations (`MigrateAsync`), run `DataSeeder.SeedAsync()`
9. **Hangfire** — register `RefreshStockPricesJob` as recurring with cron from config
10. **Global error handling** — wrap everything in try/catch with `Log.Fatal` for startup failures

The `OnChallenge` handler prevents ASP.NET's default behavior (which would return a bare 401 with `WWW-Authenticate` header) and instead writes a ProblemDetails JSON response matching the format our `ExceptionHandlingMiddleware` produces. This ensures the frontend always receives `{ status: 401, title: "Unauthorized", detail: "..." }` whether the 401 comes from JWT validation failure or from a thrown `UnauthorizedException`.

- [ ] **Step 1: Replace Program.cs**

`src/backend/API/Program.cs`
```csharp
using System.Text;
using FluentValidation;
using FluentValidation.AspNetCore;
using Hangfire;
using Microsoft.AspNetCore.Authentication.JwtBearer;
using Microsoft.AspNetCore.Mvc;
using Microsoft.EntityFrameworkCore;
using Microsoft.IdentityModel.Tokens;
using Microsoft.OpenApi.Models;
using Serilog;
using StockPredictor.API.Middleware;
using StockPredictor.Application.Validators;
using StockPredictor.Infrastructure;
using StockPredictor.Infrastructure.Jobs;
using StockPredictor.Infrastructure.Persistence;
using StockPredictor.Infrastructure.Seeding;

Log.Logger = new LoggerConfiguration()
    .WriteTo.Console()
    .CreateBootstrapLogger();

try
{
    var builder = WebApplication.CreateBuilder(args);

    // Serilog
    builder.Host.UseSerilog((ctx, config) =>
        config.ReadFrom.Configuration(ctx.Configuration)
              .WriteTo.Console()
              .WriteTo.File("logs/api-.txt", rollingInterval: RollingInterval.Day)
              .Enrich.FromLogContext());

    // Infrastructure (DB, repos, services, ML client, Hangfire)
    builder.Services.AddInfrastructure(builder.Configuration);

    // Controllers + FluentValidation
    builder.Services.AddControllers();
    builder.Services.AddFluentValidationAutoValidation();
    builder.Services.AddValidatorsFromAssemblyContaining<RegisterRequestValidator>();

    // JWT Authentication
    var jwtKey = builder.Configuration["Jwt:Key"]
        ?? throw new InvalidOperationException("Jwt:Key is not configured.");
    builder.Services.AddAuthentication(JwtBearerDefaults.AuthenticationScheme)
        .AddJwtBearer(options =>
        {
            options.TokenValidationParameters = new TokenValidationParameters
            {
                ValidateIssuer = true,
                ValidateAudience = true,
                ValidateLifetime = true,
                ValidateIssuerSigningKey = true,
                ValidIssuer = builder.Configuration["Jwt:Issuer"],
                ValidAudience = builder.Configuration["Jwt:Audience"],
                IssuerSigningKey = new SymmetricSecurityKey(Encoding.UTF8.GetBytes(jwtKey))
            };

            options.Events = new JwtBearerEvents
            {
                OnChallenge = async context =>
                {
                    context.HandleResponse();
                    context.Response.StatusCode = StatusCodes.Status401Unauthorized;
                    context.Response.ContentType = "application/problem+json";

                    var detail = string.IsNullOrEmpty(context.ErrorDescription)
                        ? "Authentication is required to access this resource."
                        : context.ErrorDescription;

                    await context.Response.WriteAsJsonAsync(new ProblemDetails
                    {
                        Status = StatusCodes.Status401Unauthorized,
                        Title = "Unauthorized",
                        Detail = detail
                    });
                },
                OnForbidden = async context =>
                {
                    context.Response.StatusCode = StatusCodes.Status403Forbidden;
                    context.Response.ContentType = "application/problem+json";

                    await context.Response.WriteAsJsonAsync(new ProblemDetails
                    {
                        Status = StatusCodes.Status403Forbidden,
                        Title = "Forbidden",
                        Detail = "You do not have permission to access this resource."
                    });
                }
            };
        });

    builder.Services.AddAuthorization();

    // CORS — origins from config
    var allowedOrigins = builder.Configuration.GetSection("Cors:AllowedOrigins").Get<string[]>() ?? [];
    builder.Services.AddCors(opts =>
        opts.AddPolicy("FrontendPolicy", policy =>
            policy.WithOrigins(allowedOrigins)
                  .AllowAnyHeader()
                  .AllowAnyMethod()));

    // Swagger with JWT support
    builder.Services.AddEndpointsApiExplorer();
    builder.Services.AddSwaggerGen(c =>
    {
        c.SwaggerDoc("v1", new OpenApiInfo { Title = "StockPredictor API", Version = "v1" });
        c.AddSecurityDefinition("Bearer", new OpenApiSecurityScheme
        {
            In = ParameterLocation.Header,
            Description = "Enter: Bearer {your_token}",
            Name = "Authorization",
            Type = SecuritySchemeType.ApiKey,
            Scheme = "Bearer"
        });
        c.AddSecurityRequirement(new OpenApiSecurityRequirement
        {
            {
                new OpenApiSecurityScheme
                {
                    Reference = new OpenApiReference
                    {
                        Type = ReferenceType.SecurityScheme,
                        Id = "Bearer"
                    }
                },
                []
            }
        });
    });

    var app = builder.Build();

    // Middleware pipeline (order matters)
    app.UseMiddleware<CorrelationIdMiddleware>();
    app.UseMiddleware<ExceptionHandlingMiddleware>();
    app.UseSerilogRequestLogging();

    if (app.Environment.IsDevelopment())
    {
        app.UseSwagger();
        app.UseSwaggerUI();
        app.UseHangfireDashboard("/hangfire");
    }

    app.UseCors("FrontendPolicy");
    app.UseAuthentication();
    app.UseAuthorization();
    app.MapControllers();

    // Apply migrations and seed default stocks
    using (var scope = app.Services.CreateScope())
    {
        var db = scope.ServiceProvider.GetRequiredService<AppDbContext>();
        await db.Database.MigrateAsync();

        var seeder = scope.ServiceProvider.GetRequiredService<DataSeeder>();
        await seeder.SeedAsync();
    }

    // Register recurring Hangfire job
    RecurringJob.AddOrUpdate<RefreshStockPricesJob>(
        "refresh-stock-prices",
        job => job.ExecuteAsync(),
        builder.Configuration["Hangfire:RefreshCron"] ?? "0 * * * *"
    );

    await app.RunAsync();
}
catch (Exception ex) when (ex is not HostAbortedException)
{
    Log.Fatal(ex, "Application startup failed");
}
finally
{
    Log.CloseAndFlush();
}
```

## Task 22: AuthController

**Files:**
- Create: `src/backend/API/Controllers/AuthController.cs`

Two endpoints, neither requiring `[Authorize]`:
- `POST /api/auth/register` — takes `RegisterRequest` (validated by `RegisterRequestValidator`), returns `201 Created` with `AuthResponse` (token + user info). Can throw `ConflictException` (409) if email/username taken.
- `POST /api/auth/login` — takes `LoginRequest` (validated by `LoginRequestValidator`), returns `200 OK` with `AuthResponse`. Can throw `UnauthorizedException` (401) if credentials are invalid.

Both delegate entirely to `IAuthService`. FluentValidation auto-validates request bodies before the action executes — invalid requests get a 400 with validation errors automatically (no code needed in the controller).

- [ ] **Step 1: Create AuthController**

`src/backend/API/Controllers/AuthController.cs`
```csharp
using Microsoft.AspNetCore.Mvc;
using StockPredictor.Application.DTOs.Auth;
using StockPredictor.Application.Interfaces.Services;

namespace StockPredictor.API.Controllers;

[ApiController]
[Route("api/auth")]
public class AuthController : ControllerBase
{
    private readonly IAuthService _auth;

    public AuthController(IAuthService auth) => _auth = auth;

    [HttpPost("register")]
    [ProducesResponseType(typeof(AuthResponse), StatusCodes.Status201Created)]
    [ProducesResponseType(typeof(ProblemDetails), StatusCodes.Status400BadRequest)]
    [ProducesResponseType(typeof(ProblemDetails), StatusCodes.Status409Conflict)]
    public async Task<IActionResult> Register([FromBody] RegisterRequest request)
    {
        var response = await _auth.RegisterAsync(request);
        return Created(string.Empty, response);
    }

    [HttpPost("login")]
    [ProducesResponseType(typeof(AuthResponse), StatusCodes.Status200OK)]
    [ProducesResponseType(typeof(ProblemDetails), StatusCodes.Status400BadRequest)]
    [ProducesResponseType(typeof(ProblemDetails), StatusCodes.Status401Unauthorized)]
    public async Task<IActionResult> Login([FromBody] LoginRequest request)
    {
        var response = await _auth.LoginAsync(request);
        return Ok(response);
    }
}
```

## Task 23: StocksController

**Files:**
- Create: `src/backend/API/Controllers/StocksController.cs`

All endpoints require `[Authorize]`. The `UserId` property reads the user's GUID from the JWT `NameIdentifier` claim (set by `AuthService.GenerateToken` as `ClaimTypes.NameIdentifier`).

Five endpoints:
- `GET /api/stocks/watchlist` — returns user's watchlist with latest prices, signals. Delegates to `IWatchlistService.GetAsync(userId)`.
- `POST /api/stocks/watchlist` — adds ticker to watchlist. Takes `AddToWatchlistRequest` body (validated by `AddToWatchlistRequestValidator`). Returns `201 Created`. Can throw `NotFoundException` (404) if ticker unknown and ML can't find it, `ConflictException` (409) if already in watchlist.
- `DELETE /api/stocks/watchlist/{ticker}` — removes from watchlist. Returns `204 NoContent`. Can throw `NotFoundException` (404).
- `GET /api/stocks/search?q=` — searches stocks by ticker or name. Returns empty list for blank query. Delegates to `IStockService.SearchAsync(query, userId)`. The `userId` is needed to set `IsInWatchlist` on results.
- `GET /api/stocks/{ticker}` — returns full stock detail with all price history. Delegates to `IStockService.GetDetailAsync(ticker)`. Can throw `NotFoundException` (404).

- [ ] **Step 1: Create StocksController**

`src/backend/API/Controllers/StocksController.cs`
```csharp
using System.Security.Claims;
using Microsoft.AspNetCore.Authorization;
using Microsoft.AspNetCore.Mvc;
using StockPredictor.Application.DTOs.Stocks;
using StockPredictor.Application.DTOs.Watchlist;
using StockPredictor.Application.Interfaces.Services;

namespace StockPredictor.API.Controllers;

[ApiController]
[Route("api/stocks")]
[Authorize]
public class StocksController : ControllerBase
{
    private readonly IStockService _stocks;
    private readonly IWatchlistService _watchlist;

    public StocksController(IStockService stocks, IWatchlistService watchlist)
    {
        _stocks = stocks;
        _watchlist = watchlist;
    }

    private Guid UserId => Guid.Parse(User.FindFirstValue(ClaimTypes.NameIdentifier)!);

    [HttpGet("watchlist")]
    [ProducesResponseType(typeof(List<WatchlistItemDto>), StatusCodes.Status200OK)]
    public async Task<IActionResult> GetWatchlist() =>
        Ok(await _watchlist.GetAsync(UserId));

    [HttpPost("watchlist")]
    [ProducesResponseType(StatusCodes.Status201Created)]
    [ProducesResponseType(typeof(ProblemDetails), StatusCodes.Status400BadRequest)]
    [ProducesResponseType(typeof(ProblemDetails), StatusCodes.Status404NotFound)]
    [ProducesResponseType(typeof(ProblemDetails), StatusCodes.Status409Conflict)]
    public async Task<IActionResult> AddToWatchlist([FromBody] AddToWatchlistRequest request)
    {
        await _watchlist.AddAsync(UserId, request.Ticker);
        return Created(string.Empty, null);
    }

    [HttpDelete("watchlist/{ticker}")]
    [ProducesResponseType(StatusCodes.Status204NoContent)]
    [ProducesResponseType(typeof(ProblemDetails), StatusCodes.Status404NotFound)]
    public async Task<IActionResult> RemoveFromWatchlist(string ticker)
    {
        await _watchlist.RemoveAsync(UserId, ticker.ToUpper());
        return NoContent();
    }

    [HttpGet("search")]
    [ProducesResponseType(typeof(List<StockSearchResultDto>), StatusCodes.Status200OK)]
    public async Task<IActionResult> Search([FromQuery] string q)
    {
        if (string.IsNullOrWhiteSpace(q))
            return Ok(new List<StockSearchResultDto>());

        return Ok(await _stocks.SearchAsync(q.Trim(), UserId));
    }

    [HttpGet("{ticker}")]
    [ProducesResponseType(typeof(StockDetailDto), StatusCodes.Status200OK)]
    [ProducesResponseType(typeof(ProblemDetails), StatusCodes.Status404NotFound)]
    public async Task<IActionResult> GetDetail(string ticker) =>
        Ok(await _stocks.GetDetailAsync(ticker.ToUpper()));
}
```

## Task 24: PredictionsController

**Files:**
- Create: `src/backend/API/Controllers/PredictionsController.cs`

All endpoints require `[Authorize]`. Two endpoints:
- `POST /api/predictions` — takes `PredictRequest` body (validated by `PredictRequestValidator`: ticker must match `^[A-Z]{1,5}(\.[A-Z]{1,2})?$`, horizon must be `3m`, `6m`, or `1y`). Returns `200 OK` with `PredictionDto`. Delegates to `IPredictionService.GetOrCreateAsync`. Can throw `NotFoundException` (404) if stock not in DB, `HorizonNotSupportedException` (501) if horizon not yet supported, `MlServiceUnavailableException` (503) if ML service is down.
- `GET /api/predictions/{ticker}?horizon=3m` — returns the latest prediction for a ticker/horizon. Returns `200 OK` with `PredictionDto` if found, `404 NotFound` if not. Delegates to `IPredictionService.GetLatestAsync`.

- [ ] **Step 1: Create PredictionsController**

`src/backend/API/Controllers/PredictionsController.cs`
```csharp
using Microsoft.AspNetCore.Authorization;
using Microsoft.AspNetCore.Mvc;
using StockPredictor.Application.DTOs.Predictions;
using StockPredictor.Application.Interfaces.Services;

namespace StockPredictor.API.Controllers;

[ApiController]
[Route("api/predictions")]
[Authorize]
public class PredictionsController : ControllerBase
{
    private readonly IPredictionService _predictions;

    public PredictionsController(IPredictionService predictions) => _predictions = predictions;

    [HttpPost]
    [ProducesResponseType(typeof(PredictionDto), StatusCodes.Status200OK)]
    [ProducesResponseType(typeof(ProblemDetails), StatusCodes.Status400BadRequest)]
    [ProducesResponseType(typeof(ProblemDetails), StatusCodes.Status404NotFound)]
    [ProducesResponseType(typeof(ProblemDetails), StatusCodes.Status501NotImplemented)]
    [ProducesResponseType(typeof(ProblemDetails), StatusCodes.Status503ServiceUnavailable)]
    public async Task<IActionResult> Predict([FromBody] PredictRequest request) =>
        Ok(await _predictions.GetOrCreateAsync(request.Ticker.ToUpper(), request.Horizon));

    [HttpGet("{ticker}")]
    [ProducesResponseType(typeof(PredictionDto), StatusCodes.Status200OK)]
    [ProducesResponseType(StatusCodes.Status404NotFound)]
    public async Task<IActionResult> GetLatest(string ticker, [FromQuery] string horizon = "3m")
    {
        var result = await _predictions.GetLatestAsync(ticker.ToUpper(), horizon);
        return result == null ? NotFound() : Ok(result);
    }
}
```

## Task 25: EF Core Migration

**Prerequisites:**
- PostgreSQL must be running via Docker: `docker-compose up db -d`
- The `dotnet-ef` global tool must be installed. If not: `dotnet tool install --global dotnet-ef`
- The ML service does **not** need to be running for this step.

This task generates the initial EF Core migration from the `AppDbContext` and its 5 entity configurations (`UserConfiguration`, `StockConfiguration`, `StockPriceConfiguration`, `WatchlistItemConfiguration`, `PredictionConfiguration`). The migration creates the following database objects:

- **Tables:** `Users`, `Stocks`, `StockPrices`, `WatchlistItems`, `Predictions`
- **Unique indexes:** `Users.Email`, `Users.Username`, `Stocks.Ticker`, `StockPrices(StockId, Date)`, `WatchlistItems(UserId, StockId)`, `Predictions(StockId, Horizon, ExpiresAt)`
- **Foreign keys:** `StockPrices → Stocks` (cascade), `WatchlistItems → Users` (cascade), `WatchlistItems → Stocks` (restrict), `Predictions → Stocks` (cascade)
- **Hangfire schema:** auto-created by Hangfire on first startup (not part of EF migration)

The migration files are generated artifacts — they should be committed to version control but never hand-edited.
